# odysseus — Element Decomposition and Stack Mapping

Date: 2026-07-04
Source project: `pewdiepie-archdaemon/odysseus` (branch `dev`, HEAD `1f6dc805`, read 2026-07-04) — a self-hosted AI workspace (chat, agents, deep research, documents, email, notes, calendar, local model workflows). Python/FastAPI backend + vanilla-JS PWA. — <https://github.com/pewdiepie-archdaemon/odysseus>
Decision: **inspiration-first, PROPOSED 2026-07-04** — no `adopt` is available for any element (license, below); the useful split is `rebuild` (reimplement the concept on our stack) vs `knowledge` (reference/counter-example, no increment) vs `reject` vs `quarantine`. Verdicts below are proposed for arbitration; nothing ships from this document until ratified.
Scope: personal forge ecosystem only.

## Why this document

The brief was "reprendre tout le principe d'odysseus pour renforcer bolt-\* et le reste de la stack, récupérer les meilleurs éléments". Two facts reframe it before any landing:

1. **The "principle" is our anti-pattern.** Odysseus is a single monolithic deployable — one FastAPI process mounting 54 flat route files (`routes/`) over ~95 flat service modules (`src/`), all sharing one SQLite DB, one auth store, one config. That is the exact opposite of the ratified layer model (ADR 0033: owning-domain prefixes + CI-gated `deployment_class`; bounded-context isolation; contract-first; Rust at core). Adopting "the principle" would undo the architecture. So the principle itself is quarantined (E1); what is worth harvesting is the **catalogue of capabilities** and a **short list of genuinely distinctive patterns**.

2. **~80 % of its capabilities land outside `bolt`.** The overlap recon mapped its surface onto rumble-\* (products), gear-\* (substrate), wrench-\* (factory tooling), portal-\* (design), and only a thin slice onto bolt (agent-runtime supervision patterns). Per ADR 0022 (external projects strengthen existing repos), this document decomposes odysseus element by element so each concept lands on the right layer — or is explicitly rejected.

Method precedent: `codebase-memory-mcp-decomposition.md` (PR #3, accepted 2026-07-02) and `meilisearch-decomposition.md` (PR #6/#11, accepted 2026-07-02).

Owner arbitration recorded up front (2026-07-04): (a) decompose the **whole** forge, not just bolt; (b) email + calendar are treated as **serious product candidates** (product cards for `rumble-mail` / `rumble-cal` in the Product cards section) — repo _creation_ stays gated on ratification; (c) code-reading posture is **read-to-extract-patterns, zero copy** (see Method).

## Method

Taxonomy reused from `github-stars-stack-audit.md`:

- Disposition: `rebuild` (reimplement the concept on our stack, with a target layer/increment), `knowledge` (reference material or counter-example, no increment), `reject`, `quarantine`. **`adopt` is excluded for every element** — see the license fact below.
- Layer: `rumble`, `portal`, `bolt`, `wrench`, `gear`, `cross-layer`, `outside`.
- Conditional triggers gate dispositions where relevant ("adopt-trigger: real need emerges" → here reads as "rebuild-trigger", since adopt is off the table).
- `rebuild` and `knowledge` carry a parenthetical qualifier for precision (same convention as the meilisearch/codebase-memory maps): `(pattern)` a reusable design applied across layers; `(method)` an evaluation or test protocol; `(product-gated)` a product feature whose rebuild is gated on product ratification; `(trigger)` a rebuild deferred until a named factual gate fires (no proven consumer yet); `(concept)`/`(design note)` a bounded idea or reference for future design; `(counter/reference)` a thing understood as an anti-pattern or comparison.

**License posture (binding, axis #1 sovereignty).** Odysseus is **AGPL-3.0-or-later** (`LICENSE`, confirmed; `README.md:76`). AGPL is banned by the forge license policy (MIT/Apache/MPL floor). Consequences, applied throughout:

- **No `adopt`, no dependency, no install, no code copy or line-by-line translation.** Ideas, mechanisms, and API shapes are not copyrightable; their _expression_ is. Every `rebuild` verdict means: understand the mechanism from the source, then reimplement from scratch in Rust on our stack, with no derivation from odysseus's source text.
- The source was **read** (shallow clone in a scratchpad, never committed, never a submodule) purely to describe mechanisms accurately. This spec contains **prose and identifiers only — zero code blocks**.
- One derived caveat that also lands as a sovereignty note (E36/E43): odysseus's own optional dependency **PyMuPDF is AGPL-3.0** — a transitive trap the forge must never inherit.

## Reference facts (verified 2026-07-04, HEAD `1f6dc805`)

- **Shape:** monolith. `app.py` (~1,150 lines) mounts the route layer — 54 files in `routes/` (via `setup_*_routes()`) — over 97 flat modules in `src/` (top level) plus domain packages in `services/`. Four Docker services in the default compose: the app, ChromaDB (vector store), SearXNG (meta-search), ntfy (push); optional GPU model containers. Multi-platform launchers: `launcher.py`, `build-macos-app.sh`, `build-windows-portable.ps1` (PyInstaller), `install-service.sh` (systemd).
- **License:** AGPL-3.0-or-later (`LICENSE`). Community reports place a MIT→AGPL relicensing ~2 weeks after launch. Optional dep **PyMuPDF is AGPL** (`requirements-optional.txt`); `nh3` (HTML sanitizer) is a **mandatory** dep.
- **Maturity:** the read HEAD (`1f6dc805`) is dated 2026-07-03 on the default branch `dev` (no stable release); public reporting places the launch ~1 month prior (the shallow clone does not carry full history to confirm the age directly). `ROADMAP.md` header is literally "I don't know what I'm doing, help"; the codebase is widely characterized externally as AI-generated, though the repo does not self-describe that way and no independent security audit is referenced. Large open-issue backlog.
- **Security model (`THREAT_MODEL.md`, `SECURITY.md`):** trusted-users-on-a-private-network only; `AUTH_ENABLED=true`, `LOCALHOST_BYPASS=false`, internal services bind `127.0.0.1` by default. **Documented, accepted gaps:** (1) _no shell/filesystem sandbox_ — agent `bash`/`read_file`/`write_file` run as the app user with no egress filtering (`THREAT_MODEL.md:75`), gated only by admin-only authorization; (2) SSRF via a `base_url` parameter (fix PR referenced); (3) prompt injection treated as first-class but unsolved at the model layer.
- **Notable engineering (verified in code):** a formalized untrusted-context wrapper for prompt-injection defense (`src/prompt_security.py`), a DNS-pinning SSRF transport (`src/url_safety.py`, `services/search/content.py`), a fail-closed tool-permission matrix (`src/tool_security.py`), token budgeting + context compaction for small models (`src/context_budget.py`, `src/context_compactor.py`), bidirectional CalDAV sync with tombstones (`src/caldav_sync.py`, `src/caldav_writeback.py`), a collection-time test taxonomy (`tests/_taxonomy.py`, `tests/conftest.py`), and SHA-pinned supply-chain CI gates (`.github/workflows/`).
- **CI posture:** blocking gates are mechanical only — Python/JS **syntax**, gitleaks (pinned + SHA-verified), actionlint, zizmor, hadolint, dependency-review. **`pytest` is non-blocking** (`continue-on-error: true` at `.github/workflows/ci.yml:22,109`, commented "known flaky / environment-dependent"). No `mypy`/`ruff`/`black` in CI.

## Deep dives (implementation-relevant)

The forge-relevant elements are E1–E43; E44 records the rejected long tail so the decomposition is exhaustive rather than cherry-picked. The three patterns below are the only ones with a concrete (if triggered) rebuild path.

### 1. E10 — DNS-pinning SSRF transport (reference pattern, rebuild-triggered)

The mechanism (from `src/url_safety.py` + `services/search/content.py`, described, not copied): before any outbound fetch, resolve the hostname to its IP list and classify each IP (reject link-local `169.254/16`, multicast, reserved, unspecified; optionally reject private `10/8`, `172.16/12`, `192.168/16`, and loopback under a `block_private` flag). Then build a transport that **pins the TCP connect to a pre-resolved public IP** while still sending the correct SNI/Host, so a second DNS lookup at connect time cannot swap in a private IP — closing the classic DNS-rebinding TOCTOU that a resolve-then-connect check leaves open.

Transposed to the forge: any component that fetches attacker-influenceable URLs needs this — but **none does today**. gear-loader declares a `NetworkPolicy` enum (`Disabled` / `SingleUrl` / `BoundedCrawl`) that defaults to `Disabled`; wrench-inspect makes no outbound requests. So this is a reference pattern, not a pending rebuild. When the first gear-loader increment actually enables `SingleUrl`/`BoundedCrawl`, rebuild it as a small Rust helper (resolve → classify → pinned connector over `reqwest`/`hyper`) with two fixes for the caveats the recon found: (a) unify the classification so the config-time check and the fetch-time check agree (odysseus's two guards diverge on loopback), and (b) return an explicit error on empty content rather than `success:true` with an empty body. Rebuild-trigger: the first gear-loader network-fetch increment.

### 2. E22 + E23 — Untrusted-context envelope and fail-closed tool gating

**E22 (untrusted-context envelope).** External content — web results, emails, memories, tool output, even MCP tool _descriptions_ — is wrapped in explicit guard markers with the enclosed text escaped so it cannot forge the closing delimiter, and the message is tagged `{trusted:false, source:label}`. A policy preamble in the system role tells the model that guarded content is data, never instructions. This is a clean, testable shape (escape + tag + label) and is **adjacent to, not a duplicate of, ADR 0015**: ADR 0015 makes wrench-loader emit a hostile-content evidence report at ingestion; this is the runtime envelope a model-facing surface would use. No forge surface feeds untrusted text to a model today (the harness is the runtime), so it is reference-only until one does. Honest limit to carry over: this is a _mitigation_, not enforcement — the model can still be jailbroken; it belongs alongside, not instead of, the structural defenses (planning-only, refusal-first).

**E23 (fail-closed tool gating).** Two ideas transfer directly to cos-matic's gate model and ADR 0028's closed permission vocabulary: (a) the gate **fails closed** — a non-string or unknown tool name is blocked, not allowed; (b) **plan mode is expressed as an allowlist** (enumerate the read-only tools; deny by subtraction) rather than a blocklist, so a newly added tool is denied-by-default until explicitly cleared. Both are safety-monotonic defaults the forge should mirror when cos-matic maps intents to permitted actions.

### 3. E32 — Blind comparison as a wrench-inspect Eval Lab method

Server-side randomized A/B with model names withheld until the vote is recorded, then mapped back through a stored blind-mapping — a bias-control protocol. It slots next to the two evaluation methods already captured (codebase-memory-mcp E21 blind 3-pass LLM judge; meilisearch declarative benchmark workloads) as a third Eval-Lab pattern for wrench-inspect: when comparing two models/prompts/configs, randomize presentation, withhold identity, record the raw vote, reveal only after. Caveat to design out: their owner-scoping was applied inconsistently in older code (a real leak bug) — the rebuild scopes every read.

## Product cards — `rumble-mail` and `rumble-cal` (candidates)

Per the owner's arbitration, email and calendar are treated as serious product candidates. These are **scoping cards, not repo-creation** — creation stays gated on ratification and on the M1 workspace/identity lock (ADR 0028) that every rumble product now depends on.

### `rumble-mail` (candidate)

- **Reason to exist (the differentiator, E14):** agent-assisted mail — summarize, draft replies in the user's writing style, classify (phishing/marketing/receipts), surface urgency, and extract calendar/tracking items from message bodies. A plain IMAP/SMTP client is not a product; the triage layer is.
- **Core capabilities:** IMAP polling with connection pooling + 3-layer cache + UID addressing (E12); compose/sanitize/send + scheduled send (E13); the concern-split SQLite schema (E15) — rebuilt on the product's elected storage.
- **Stack fit:** Rust core + Dioxus web shell (ADR 0032); Biscuit delegated authorization + `workspace-identity` for multi-user (ADR 0028); portal tokens for UI. Contracts frozen first (forge doctrine), UI second.
- **Shared with the forge (gear):** contacts store (E19) and the untrusted-context envelope (E22) — inbound mail is hostile content by definition.
- **Technical difficulty (not architecture):** the hard part is not the shape (standard IMAP/SMTP) but provider-quirk breadth (Gmail folder naming; **Outlook/O365 requires OAuth**, which odysseus does _not_ implement — basic auth is disabled by Microsoft) and hostile-input parsing (untrusted-body→LLM must not use their redos-prone regex). Large surface area.
- **Rebuild-trigger:** an explicit decision that mail is a forge product; blocked on M1 (workspace/identity) like canvas.

### `rumble-cal` (candidate)

- **Reason to exist:** a sovereign, local-first calendar that syncs any standard CalDAV server (Radicale/Nextcloud/iCloud/Google) with agent-assisted natural-language entry.
- **Core capabilities:** CalDAV pull with a stable hashed calendar id and safe-prune (E16); write-back with tombstoned deletes (E17) — **plus a real conflict-resolution design**, which odysseus lacks (its write-back is best-effort with non-atomic ETag checks); RRULE recurrence with compound UIDs and a DoS cap (E18); NL parsing with per-request tz injection (E20).
- **Stack fit:** identical to `rumble-mail` (Rust core, Dioxus shell, Biscuit, portal tokens); shares the contacts store (E19).
- **Real cost / risks:** iCalendar/RRULE correctness (timezones, `UNTIL`, all-day vs timed, exdates) is the genuine difficulty; conflict resolution is a design problem odysseus deferred and the forge must not.
- **Rebuild-trigger:** paired with `rumble-mail` (shared substrate) or an explicit standalone-calendar decision; blocked on M1.
