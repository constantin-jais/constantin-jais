# Depot Artifact Manifest Contract

Status: Draft / P0 substrate contract.

## ArtifactManifest

Owner: `gear-depot`.

Purpose: describe packageable artifacts with integrity, provenance, retention,
revocation, and distribution metadata.

```json
{
  "manifest_id": "manifest_01",
  "artifact": {
    "artifact_id": "art_01",
    "artifact_type": "spec_package | handoff_payload | curated_export | learning_export | release_asset | inspection_report",
    "producer": "rumble-canvas | rumble-lm | rumble-feed-mind | rumble-cos | wrench-inspect | gear-cable",
    "version": "1.0.0",
    "hash": "sha256:...",
    "created_at": "2026-06-30T00:00:00Z"
  },
  "package_type": "json_bundle | tar | zip | binary | container | registry_package",
  "checksums": [
    {
      "algorithm": "sha256",
      "value": "..."
    }
  ],
  "provenance_id": "prov_01",
  "retention": {
    "policy_ref": "optional",
    "expires_at": "optional",
    "revoked_at": "optional",
    "delete_after": "optional"
  },
  "distribution": {
    "channels": [],
    "install_floor": "optional",
    "published_at": "optional"
  }
}
```

Rules:

- `manifest_id` and `provenance_id` must be non-empty.
- `artifact.manifest_ref` must equal `manifest_id`.
- Every manifest must include at least one checksum.
- `sha256` is required for P0; artifact hashes use `sha256:<64 hex chars>` and
  checksum values use 64 hexadecimal characters for the declared SHA-256
  algorithm.
- Signatures are future-compatible but not mandatory in P0.
- `retention.revoked_at` marks artifact trust/availability state; it does not
  rewrite prior checksums.
- `retention.expires_at`, `retention.revoked_at`, `retention.delete_after`, and
  `distribution.published_at` must be RFC3339 / ISO 8601 with an explicit
  offset when present.
- `distribution.install_floor` is supplied by Gear Cable for tool releases.

## Current Wrench Evidence Proof

The first report-artifact fixture represents a `wrench.evidence_report.v0.1` as a Gear `ArtifactManifest`:

```text
ecosystem/specs/gear/fixtures/artifacts/wrench-portal-evidence-manifest.valid.json
```

It is generated by Gear Depot from a local Wrench evidence report and keeps the boundary explicit: Wrench owns findings/checks, Gear owns artifact integrity, manifest metadata, retention, and distribution state.

## Gear Cable Relationship

`gear-cable` owns release planning, target/platform matrices, checksums,
signatures, install floors, and build provenance for Rust-first tools.

`gear-depot` owns artifact verification, trust state, cache/proxy policy,
retention, revocation, and distribution availability.

Flow:

```text
Rumble/Wrench/Bolt tool source
-> gear-cable ReleaseManifest and build provenance
-> build outputs and checksums
-> gear-depot ArtifactManifest
-> verified distribution/cache/proxy
```

Gear Cable must not become a registry or policy cache. Gear Depot must not own
release planning.

## Reproducibility and Secrets

- Manifests must be hashable from canonical JSON with deterministic key order.
- Build and tool references may be included in provenance metadata, but secrets
  must never be embedded.
- Manifest validation must reject secret-like metadata keys before persistence
  or distribution.
- Artifacts that cannot be reproduced must state that fact in provenance
  metadata; Depot still verifies integrity of the bytes it stores.
